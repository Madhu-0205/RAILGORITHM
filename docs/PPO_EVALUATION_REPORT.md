# RAILGORITHM v2.9 — PPO REINFORCEMENT LEARNING EVALUATION & GOVERNANCE REPORT

## 1. Architectural Scope & Governance Boundaries

The Proximal Policy Optimization (PPO) reinforcement learning model in RAILGORITHM acts strictly as a **candidate ranking policy**, not an autonomous controller.

### Absolute Safety Invariant:
```
       PPO Policy Ranking
               ↓
    CANNOT bypass CP-SAT Solver
               ↓
CANNOT bypass Independent Validator
               ↓
 CANNOT execute autonomous commands
```
- PPO evaluates only actions that have already been generated by heuristic logic or the CP-SAT solver.
- Every candidate is independently re-validated by the rule-based constraint validator.
- If PPO ranks an invalid candidate first, the independent validator rejects it immediately.
- Disagreement between PPO and CP-SAT is preserved and displayed to the human controller; it is **never silently suppressed**.

## 3. Disagreement Detection & Transparency

When PPO and CP-SAT prefer different candidates (e.g. Scenario 18):
1. **`disagreement: true`**: Flagged in recommendation metadata.
2. **`evidence_status: "MODEL_DISAGREEMENT"`**: Highlights the variance in operational philosophy.
3. **`disagreement_detail`**:
   - `ppo_top_candidate_id`: ID of PPO preferred action.
   - `cpsat_candidate_id`: ID of CP-SAT schedule action.
   - `selection_rule`: Transparently documented selection rule (the candidate with the lowest measured weighted delay in cloned simulation is recommended).

This transparency ensures operating staff understand the trade-offs between model heuristics and global optimization bounds.
